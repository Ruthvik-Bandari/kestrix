# Kestrix plugin demo

A scripted demo of the `kestrix` Claude Code plugin: a tiny project with planted security problems, the exact
prompts to give Claude, and the hook output each step produces. How to record it is in
[`docs/demo/record.md`](record.md).

## What is here

| Path | What it is |
| --- | --- |
| [`sample-project/`](sample-project/) | A notes service with four planted problems: SQL built with an f-string, `shell=True`, MD5 for passwords and an `innerHTML` sink. Its `.kestrix.json` turns the Stop gate on. |
| [`setup_demo.py`](setup_demo.py) | Copies `sample-project/` to a new directory and adds `settings_local.py` with a fake GitHub token. The token is assembled when the script runs, so no token-shaped string is committed. It was never issued and grants nothing. |
| [`prompts.md`](prompts.md) | The prompts, in order, with what you should see after each one. |
| [`expected/`](expected/) | The exact output of the scanner and of the plugin's hook script for each scripted step. |

The files in `expected/` are generated by `uv run python scripts/build_demo_expected.py`, which builds the
demo project in a temporary directory and runs the plugin's real hook script on the hook JSON Claude Code
sends. `tests/integrations/test_plugin_demo.py` fails when they drift from the current scanner. Temporary
paths appear as `<demo>`.

## Run it

You need `kestrix-scan` on PATH (`pip install kestrix-scan`, or `uv tool install kestrix-scan`), `python3`, and
the plugin installed (see the plugin README). From a checkout of this repository:

```bash
python3 docs/demo/setup_demo.py ~/kestrix-demo
cd ~/kestrix-demo
claude
```

Then follow [`prompts.md`](prompts.md). Nothing in the demo uses the network.

Claude writes its own code, so its fixes and wording differ between runs. The scanner and hook output for the
scripted steps (1 to 3) are deterministic. Line numbers can differ if Claude formats a file differently from the
prompt.
