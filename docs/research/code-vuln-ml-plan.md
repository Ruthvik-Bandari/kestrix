# Learned code-vulnerability model: data, model and evaluation plan (ADR 0005, part 3)

Status: plan, 2026-10-19. Nothing has been downloaded or trained yet. This page summarizes a literature and
license survey. Every claim links to its source. It is not legal advice; licensing decisions should be reviewed
by counsel before any weights ship.

## Licensing principles (decided before any download)

1. **A dataset's license covers the compilation, not the code inside it.** Mined functions keep their projects'
   own licenses, often GPL for C/C++ ([MoreFixes notice](https://zenodo.org/records/20776007)). Whether model
   weights are a derivative work of GPL training code is legally open. BigCode left copyleft code out of The Stack
   for that reason ([The Stack](https://www.bigcode-project.org/docs/about/the-stack/)).
2. **Two tiers:**
   - the **research model** may use anything licensed for research;
   - **weights shipped with Kestrix (Apache-2.0)** train only on functions from permissively licensed
     repositories (MIT, BSD, Apache, ISC), checked per repository by SPDX license. A data card carries the
     CC BY 4.0 attributions.
3. **No labels generated by commercial models.** CleanVul (labelled by Claude) and R2Vul (labelled by GPT-4o)
   would bring in provider terms that restrict building models from their outputs. We relabel with an Apache-2.0
   open-weight model instead ([Anthropic commercial terms](https://www.anthropic.com/legal/commercial-terms)).
4. Every sample keeps `source`, `repo`, `repo_license` and `cve/ghsa` columns from day one.

### Why labels must be rebuilt

- Audited label accuracy of popular sets:

  | Dataset | Label accuracy |
  | --- | --- |
  | BigVul | 25% |
  | CrossVul | 48% |
  | CVEfixes | 52% |
  | DiverseVul | 60% |
  | PrimeVul | 86–92% |

  StarCoder2 reached 68% F1 on BigVul but 3% on PrimeVul ([PrimeVul](https://arxiv.org/html/2403.18624v2)).
- Raw Python function labels were 40% accurate, and 94% after cleaning ([PyVul](https://arxiv.org/html/2509.04260v1)).
- **Our labelling:**
  - PrimeVul's rules: a function is vulnerable only if it was the only one the fix changed, or if the NVD text
    names it or its file;
  - a cleaning pass by Qwen2.5-Coder (Apache-2.0);
  - a hand audit of at least 200 samples, reporting label accuracy.
- For JavaScript, first drop minified, bundled, `vendor/` and `dist/` files. About 47% of CVEfixes JS functions
  are labelled vulnerable, which is not plausible ([study](https://arxiv.org/html/2412.15905v2)).

## Evaluation protocol

- **Deduplicate before splitting.**
  - Hash functions with comments and whitespace normalized away.
  - Remove near-duplicates with MinHash at 0.9 or above, across all splits.
  - Drop pairs whose before and after versions are identical once normalized.
- **Splits.**
  - Temporal by CVE publication date, with the test window after the base model's release (September 2024).
  - Project-disjoint and CVE/GHSA-disjoint.
  - The test manifest is frozen and hashed, and evaluated **once** per model version.
  - Thresholds are chosen on dev only.
- **Metrics.**
  - PR-AUC and F1 at realistic prevalence (the test set is not balanced).
  - Precision@k and recall@k per repository.
  - The miss rate when the false-positive rate is capped at 0.5%, 1% and 5% (PrimeVul's VD-S).
  - Pairwise outcomes on vulnerable/patched pairs.
  - CWE top-1 and top-3 accuracy.
  - Calibration error.
  - **The precision gain of rules plus model over rules alone.**
  - Bootstrap confidence intervals resampled by project.
- **Baselines.**
  - The Kestrix rule engine.
  - Bandit and Semgrep.
  - The Purple Llama detector.
  - Random, function length, and a bag-of-words classifier.
  - Zero-shot Qwen-7B.
  - UniXcoder fine-tuned without distillation.
- **Robustness.**
  - Renaming identifiers flips predictions in 17–26% of cases ([study](https://arxiv.org/abs/2312.12575)).
  - Test with renaming and with dead code inserted.

imported lazily). Jobs: `research/hpc/vul/vul_smoke.sbatch`, `research/hpc/vul/vul_train_teacher.sbatch`, `research/hpc/vul/vul_train_student.sbatch`,
`research/hpc/vul/vul_eval.sbatch`. Logs go to `/scratch/$USER/kestrix/vul/logs/`, runs to `/scratch/$USER/kestrix/vul/runs/<run-id>/`.
Status, 2026-10-20: code and tests written, smoke job submitted; no full run yet, so no results.

**Data.** `work/split-v2.jsonl` (falling back to `work/split.jsonl`; the job fails with a clear message if neither
exists) and `work/negatives.jsonl`. Train examples are the vulnerable before-functions, their patched
after-functions (label 0) and `negative_unchanged` functions, 3 per vulnerable record by default (`--neg-ratio`,
seeded by a fixed data seed, so every training seed sees the same data). Dev serves early stopping (a dev sample
with 5 negatives per vulnerable record) and the threshold only. The training code refuses `test` and
`test_extension` (`HeldOutSplitError`, tested). `--view filtered` drops the audit strata below 0.80 label accuracy.
The records carry no file text, so the optional file context in the prompt is empty for now.

**Teacher.** Qwen2.5-Coder-7B-Instruct at revision `c03e6d358207e414f1eca0bb1891e29f1db0e242` (Apache-2.0).
LoRA r=16, alpha 32, on all attention and MLP projections; bf16 with no quantization; gradient checkpointing; up to
4,096 tokens (function code truncated beyond that). The prompt asks for `{"vulnerable": bool, "cwe": "CWE-xxx" | null}`,
and the assistant turn is opened with `{"vulnerable":`.

- **The score** is the logit of the next token ` true` minus that of ` false`, read from the pretrained
  language-model head. It is trained with binary cross-entropy.
- **Why the token logit rather than a new classification head:**
  - before training, the scorer *is* the zero-shot model, so the zero-shot baseline and the teacher differ only
    by the adapters;
  - with about 1,500 positives, starting from the model's own prior beats training a random head;
  - cross-entropy on that logit is a proper scoring rule, so `sigmoid(score)` is a probability estimate.
    The evaluation also fits Platt scaling on dev and reports calibration error before and after it.
- **CWE.** A linear head on the same hidden state ranks the 25 most frequent training CWEs (loss weight 0.2).
- **Runs.** Three seeds (one array task each) for 2 epochs, with dev PR-AUC every 200 optimizer steps (effective
  batch 16) and early stopping after 3 evaluations without gain. The run keeps the best checkpoint.
- **Soft labels.** At the end, the best teacher scores the permissive train pool (8 negatives per vulnerable
  record) for the student.

**Student.** `microsoft/unixcoder-base` at revision `5604afdc964f6c53782a6813140ade5216b99006`. Its license is
Apache-2.0 by the Hugging Face license tag and the model card, checked 2026-10-20, so ModernBERT was not needed.

- **Model.** The encoder takes up to 512 tokens and feeds a vulnerability head and a CWE head on the first token.
- **Training data.** Only the permissive-license train pool (SPDX class `permissive` from `licenses/licenses.csv`).
  The job aborts if any other example reaches it.
- **Loss.** 0.5 times BCE on the hard labels, plus 0.5 times T² times BCE against the teacher's soft labels
  (the mean logit of the given teacher runs, T = 2), plus 0.2 times CWE cross-entropy.
- **Exports.**
  - `student_fp32.pt`: a plain PyTorch state dict;
  - `student_int8.pt`: dynamic int8 `Linear` layers, with the other tensors in fp16.
  The evaluation measures their size and CPU latency.

**Evaluation** (`evaluate.py`). By default it scores all of dev, at the manifest's realistic prevalence.

- **Systems:**
  - each teacher run;
  - zero-shot Qwen-7B (the same scorer with no adapters);
  - the student;
  - the kestrix-scan rules on the function text (a function with a finding inside it is positive; the score is the
    finding count, a heuristic);
  - bag-of-words logistic regression (hashed unigrams and bigrams, standard library only: scikit-learn is not
    installed in `venv-gpu`);
  - function length;
  - random.
- **Metrics:**
  - PR-AUC, and F1 at the dev-best-F1 threshold;
  - macro precision@k and recall@k per repository (k = 1, 5, 10);
  - VD-S, the miss rate at FPR at most 0.5%, 1% and 5%;
  - pairwise outcomes on vulnerable/patched pairs;
  - CWE top-1 and top-3 on true positives;
  - ECE in 10 bins, raw and after Platt scaling;
  - rules OR model and rules AND model against rules alone, with the precision gain;
  - 95% bootstrap intervals with 1,000 resamples of whole repositories.
- **Views:** `full` and `filtered`, plus `audit_confirmed` on dev.
- **The held-out test.** `--split test --locked` adds `test` and `test_extension`. It first creates
  `reports/LOCKED_EVAL.json` exclusively and refuses if the file exists, so the test runs once. A crash leaves
  the marker without a `finished` time; deleting it is a deliberate owner decision.

## Expectations

Published results on realistic, project-disjoint data are low:
- seen-project F1 of 49% falls to 9% on unseen projects ([DiverseVul](https://arxiv.org/abs/2304.00409));
- models are near chance at telling a vulnerable function from its patch
  ([Risse and Böhme](https://arxiv.org/html/2306.17193v2)).

The model is therefore framed as **"ranks functions worth reviewing"**, never as a gate. It ships only if it
measurably improves on the rules, following the same rule as the detection-repair research.

What the locked test shows:

- **Dev was optimistic.** The teacher falls from 0.381 on dev to 0.249 on test and 0.138 on the extension set, and
  its vulnerable-versus-patch accuracy from 0.32 to 0.15 and 0.07. Dev was used to pick the run, the checkpoint and

- **The teacher is still the best system on both held-out sets**, about 5x (test) and 4x (extension) the base rate.
  On test its interval clears bag-of-words; on the extension set it overlaps bag-of-words and the student.
- **The rules barely beat chance on held-out projects** (0.059 against a 0.049 base rate on test).
- **On the filtered view of test the student (0.124) edges the teacher (0.100)**, with overlapping intervals: no
  reliable difference.

Decision: the model is **not shipped** in `kestrix-scan` or the Claude Code plugin. A ranker that is right about one
time in four to seven at these thresholds, and near chance at telling a bug from its fix, would add noise to
findings. The next round, if any, must improve generalization to unseen projects (project-disjoint early stopping
and threshold selection, more diverse training repositories, seed ensembling), judged on a new held-out set, since
this test set is now spent.

### Decision rule (written into `reports/TEST2_FROZEN.json` and the `round2.py` docstring before any training)

Ship the round-2 ranker as an optional "worth a look" ranker only if on test-v2 (full view) its PR-AUC 95%
repository-bootstrap interval lies entirely above the intervals of the kestrix-scan rules and of bag-of-words, AND its
pair accuracy is at least 0.25. Pair accuracy is the share of vulnerable/patched pairs with the vulnerable version at or
above and the patched version below the validation-chosen threshold (`correct` in the C6 reports: 0.322 dev, 0.147 test,
0.071 extension; the C6 table above labels it "vulnerable scores higher", which is the separate threshold-free
`vulnerable_scores_higher`, reported here as "higher"). Variant choice on validation, also fixed beforehand: highest
validation PR-AUC plus pair-higher, ties to the simpler variant.

### Method and per-change validation

Training pool: all C6 records (train, dev, test, test_extension; the C6 test is spent) minus test-v2, regrouped by
repository and advisory ids; a seeded 15% of groups is the project-disjoint validation split (612 records, 266 projects),
the rest trains (3,170 records, 1,434 projects, against 1,561 and 942 in C6). Early stopping, checkpoint choice and
thresholds use validation only. Seed 1, one H200 job (11328167), 4 h 14 min:

| Variant | Val PR-AUC | Val pair-higher |
| --- | --- | --- |
| v0 C6 recipe on the new split | 0.440 | 0.589 |
| v1 + repository balance (weight n^-0.5) | 0.442 | 0.592 |
| **v2 + paired contrast** (logistic loss on vulnerable over patched, weight 1, pairs share a micro-batch) | 0.425 | **0.769** |
| v3 both | 0.424 | 0.737 |

Repository balance moved nothing beyond the 0.01 noise floor, so it was not adopted. Paired contrast raised pair-higher
by 0.18 for a 0.016 PR-AUC loss; v2 had the best sum (1.194) and was chosen. Final: three seeds of v2 (job 11337533, 3 h
49 min; val PR-AUC 0.425, 0.433, 0.435) and a UniXcoder student distilled from their mean logit (val PR-AUC 0.402). The
ensemble is the mean logit of the three seeds. Validation numbers use 5 negatives per vulnerable record and are not
comparable with the full-prevalence tables below.

### Decision: not shipped

On test2 the ensemble's interval clears the rules (lower bound 0.263 against the rules' upper 0.262, by a hair) but
overlaps bag-of-words (0.263 against 0.334), so the first condition fails. Pair accuracy passes on test2 (0.338) but
misses on the fresh set (0.234). The rule says not shipped, and it is not.

What did change:

- **The pair failure is addressed.** Pair-correct rose from 0.271 (C6 teacher) to 0.338 on test2 and from 0.128 to 0.234
  on the fresh set; pair-higher from 0.70 to 0.81 and from 0.56 to 0.88. This is the one improvement that held on both
  sets and on validation, and it came from the paired-contrast loss.
- **Ranking quality barely moved.** Ensemble PR-AUC beats the C6 teacher by 0.026 (test2) and 0.100 (fresh) with
  heavily overlapping intervals; the ensemble beats its best single seed by about 0.016. Nothing here is a significant
  PR-AUC gain, and the fresh set (47 records) cannot settle it.
- **Caveats.** The held-out is a dev carve-out (Python and SVEN heavy), favoring the C6 teacher, and the baselines' own
  thresholds were set on validation; the fresh set is tiny; only one recipe was ablated, with one seed per variant, so
  the 0.01 noise floor is an assumption; pre-cutoff advisories may sit in the base model's pre-training; the bag of
  words baseline is strong on this carve-out, which is mostly short SVEN-style functions.
- **Not tried (would exceed the budget or the data):** a larger genuinely-new test set (needs another GHSA refresh in
  a few months), repository balance combined with larger neg ratios, and distillation with the pair loss in the
  student. GPU time: smoke 11327915 (6 min), ablation 4.24 h, final 3.81 h, evaluation 1.21 h: about 9.4 H200 hours in
  4 jobs.
- **Archive.** The home quota is full, so the keep-set (reports, test-v2 files, split, adapters, student, scores) is
  staged at `/scratch/$USER/kestrix/vul2-archive-20261024/vul2-keep.tar.gz` and still needs a durable copy before the
  scratch purge on 2026-11-03.
